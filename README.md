# mac-storage-optimizer

让 Codex 帮你看懂 Mac 空间占用，再由你决定清理哪些内容。

A safety-first Codex Skill for inspecting macOS storage and cleaning only specifically approved items.

**扫描 → 分类 → 风险判断 → 展示方案 → 你确认 → 清理 → 验证释放空间**

这是一个可阅读、可修改的指令 Skill，不是后台清理程序。安装不会触发清理，仓库不附带自动删除脚本。

## 为什么做这个项目

我曾借助 Codex 做了一次 Mac 空间清理：可用空间从约 **51GB → 70GB**，增加约 **19GB**。这段经历让我想把“先审计、再确认、最后验证”的方法整理成可以分享的 Skill。

这是作者提供的历史案例，**不是用本仓库第一版重复测试所得，也不是效果保证**。原始案例截图使用 GiB，51→70、约19 为取整显示；日常帖子用 GB 简写。不同电脑的缓存、应用和测量口径不同，实际结果可能很小，甚至没有可清理内容。本仓库不会据此推算或编造你的清理结果。

## 它会做什么

- 只读查看磁盘容量、可用空间和主要占用来源。
- 找出值得检查的应用缓存、包管理器缓存、构建输出、更新残留等。
- 将发现分成「已核实可再生成」「需要人工判断」「默认保护」。
- 展示具体目标、大小、风险、清理方式及是否可恢复。
- 等你确认具体项目后才执行，并测量前后可用空间的变化。

“很大”“很旧”或“名字里有 cache”都不能单独证明安全。即便归为低风险，也仍须确认。

## 默认保护什么

桌面、文档、下载目录里的正式文件、照片/图库、视频、音乐、源码与 Git 仓库（包括未提交文件）、用户项目、数据库、虚拟机、Docker 数据卷、聊天与会话记录、邮件、浏览器 Profile、密码与钥匙串、SSH/GPG/加密密钥、备份、云同步内容。

`Application Support`、`Containers`、浏览器 Profile 等目录可能同时装着缓存和重要数据，只能检查具体子项。Cookie、登录状态、历史记录、IndexedDB、Local Storage、Service Worker 存储和离线数据不能直接当普通缓存删。

遇到不确定内容就保留；权限不足就如实报告。不自动使用 `sudo`，不修改 `/System`，不对父目录执行宽泛 `rm -rf`，不顺手清空废纸篓、删除快照或安排定时清理。

## 安装：复制一句话给 Codex

适用于能够访问你本机文件的 macOS Codex 环境。普通网页聊天无法直接审计你 Mac 的磁盘。

先阅读 [SKILL.md](SKILL.md)，再把下面这段发给 Codex：

```text
请从 https://github.com/abc391/mac-storage-optimizer 安装这个 Skill。
先阅读 SKILL.md，只安装 mac-storage-optimizer 的技能文件和 agents/openai.yaml，
放入你当前版本支持的用户技能目录；不要覆盖已有同名技能，也不要执行任何清理。
安装完成后确认它能被发现，告诉我实际安装路径和调用方式。
```

也可以调用内置 `$skill-installer`，让它从这个 GitHub 仓库安装；如果它不支持仓库根目录布局，就采用下面的手动安装方式。

### 手动安装（不需要学 Git）

1. 在仓库点 **Code → Download ZIP**，解压。
2. 把文件夹命名为 `mac-storage-optimizer`（去掉解压后的 `-main` 后缀）。
3. 按 [OpenAI 的本地技能文档](https://learn.chatgpt.com/docs/build-skills)，放入 `~/.agents/skills/mac-storage-optimizer/`。在 Finder 按 `⌘⇧G` 可输入目录；没有目录时先创建。已有同名文件夹时先比较，不要直接覆盖。
4. 确认结构如下；若 Skill 没出现，重启 Codex 再检查技能列表。

```text
~/.agents/skills/mac-storage-optimizer/
├── SKILL.md
└── agents/
    └── openai.yaml
```

本项目直接分享技能文件，不要求安装插件或额外清理软件。某些旧版/定制环境使用其他技能目录，请由该环境的 Codex 确认路径，避免重复安装。

## 第一次使用：建议先只扫描

```text
使用 $mac-storage-optimizer 检查这台 Mac 的空间占用。
只做只读扫描，列出具体项目、大小、用途、风险和预计可释放空间，先不要删任何东西。
```

想继续清理时：

```text
使用 $mac-storage-optimizer 帮我释放 Mac 空间。
先给出清理方案，解释哪些操作是永久删除，等我确认具体项目后再执行。
```

看过实际方案后，可以用项目编号确认，例如「我批准表格第1、3项，采用表格中说明的永久删除方式，其余保留」。不要复制这句去批准尚未展示的项目。

在部分桌面界面，可在技能选择器中选中 **Mac Storage Optimizer**；Codex CLI/IDE 支持 `$mac-storage-optimizer`。如果选择器找不到它，先检查安装路径。

## 风险与限制

- Skill 是给 AI 的流程约束，**不是操作系统级的防误删保证**。执行前仍应核对目标；重要数据应有可靠备份。
- 缓存清理可能导致重新下载、首次启动变慢或离线内容不可用。正在运行的应用和下载需要先处理活动状态。
- 移到同一磁盘的废纸篓通常不会释放空间；永久删除无法靠废纸篓恢复，必须事先说明并确认。
- APFS、快照、克隆文件、稀疏文件、后台写入及缓存再生成，会让“文件大小总和”与“可用空间增量”不同。
- 访问权限不足时只能报告部分结果；不应为了清理而默认给予全部磁盘访问权限。
- 只适用于 macOS；不承诺固定耗时或固定回收容量。第一版已做格式检查、静态安全审阅和一次只读的模拟行为审阅，未在多台真实 Mac 上进行破坏性清理测试。

## 如何反馈

在 [Issues](https://github.com/abc391/mac-storage-optimizer/issues) 点 **New issue**，描述 macOS/Codex 版本、问题、预期行为和脱敏后的相关输出。请勿上传私密文档、完整个人路径、聊天数据库、密钥或其他敏感内容。发现可疑删除建议时，请停止执行并提交反馈。

欢迎改进说明和安全边界。用例报告有助于逐步完善；不建议贡献“一键清空”的默认行为。
